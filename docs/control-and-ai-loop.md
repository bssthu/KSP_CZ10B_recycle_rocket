# 控制算法与日志迭代

## 控制器结构

脚本不是单一 PID，而是状态机加级联反馈：

```text
发射/限速重力转弯 → 高度触发分离 → 弹道/返航 → 自杀点火判定
                                           ↓
目标相对位置 → 期望横向速度 → 横向加速度 ┐
目标相对高度 → 期望下降速度 → PI 加速度  ├→ 期望推力矢量 → kOS Steering
                                           └→ 油门 = 质量×加速度/可用推力
```

每帧以回收船网零件而不是固定经纬度为目标，并用一级真实挂钩而非固定质心偏移计算相对高度、位置和表面速度。30 km 建立一次高度索引 Hermite 轨迹，13.5 km 内切入“剩余距离 → 可停车速度 → 速度阻尼”的单向停车走廊；进入 300 m 后锁存慢速阻尼，避免穿过中心后重新切回高速追逐。垂直使用目标下降速度加 PI 环，2 km 目标为 180 m/s，最后 18 m 切换近场垂直 PI。

常规垂直制动只使用最大推力的 75%，合成矢量上限为 98%，把其余权限留给横向轨迹修正。地面相对速度不低于 30 m/s 时，推力方向受 30°逆行圆锥约束；低速捕获段改用位置/速度阻尼。横向停车请求还会反算满足倾角所需的最小垂直分量，避免垂直环恰好贴住走廊时把横向制动意外削弱。

点火条件采用保守制动距离：

`d_stop = v_down² / (2 × (Tmax/m - g)) × STOP_DISTANCE_SAFETY`

当挂钩高度小于 `d_stop + BURN_ALTITUDE_MARGIN` 时进入动力段。越接近网，允许的下降速度和倾角越小；末端仍保持约 0.65 m/s 向下穿越网面，因为真实动作也是先接触索再缓冲，而不是在索上方完全悬停。

## 为什么首版不用 MPC / 强化学习

MPC 很适合同时处理推力、倾角、油量和移动甲板约束，但需要足够可信的离散动力学模型与在线优化器；纯 kOS 实现会受指令预算和矩阵工具限制。强化学习能学会 KSP 动力学，但难以解释失败并容易利用模拟器漏洞。当前的级联控制可解释、参数少、日志可诊断，适合先建立可靠基线。

后续升级顺序应是：加入 Trajectories 落点预测 → 用增益调度适配质量/TWR → 外部 Python kRPC 实现小规模 MPC → 最后才比较 RL。任何外部控制器运行时都应关闭 kOS 的 steering/throttle lock，避免两个控制器争用。

## 已做的离线回归

`tools/simulate_controller.py` 对 250 个固定随机种子工况改变：低空、中能量和高能量进场各约三分之一；模型包含大气阻力、1.5 秒长箭体姿态响应、传感延迟与闭索等待，并扰动初始高度、下降/横向速度、位置误差和可用推力加速度。回归还单独记录一级首次进入 5 m 中心区后的最大反弹，防止“最终碰到网”掩盖多次横穿船顶。

当前参数在 Python 3.10 与 3.13 下分别得到 250/250 捕获；最差入网法向速度约 1.499 m/s、横向速度 0、位置误差约 6.200 m，最长近场对准约 11 秒，其中 236/250 工况的中心反弹不超过 8 m。模型显式加入 1.5 秒横向响应滞后、低燃料下穿、30°高速圆锥和高度线性闭索；这个结果仍只证明简化模型没有明显振荡、晚点火或悬停平移，真实 KSP 还有更复杂的气动、转动惯量、发动机响应、载具弹性和坐标轴问题。

## 实飞—日志—AI 迭代

每次飞行把 `mission`、阶段、UT、高度、挂钩高度、垂直/横向速度、横向误差、油门、倾角、质量和可用推力写到：

`C:\Projects\Kerbal Space Program\Ships\Script\cz10b\telemetry.csv`

捕获插件另在 `KSP.log` 写一行 `CAPTURE` 或 `REJECT`，后者包含法向速度、横向速度和倾角。

一次迭代流程：

1. 发射前 quicksave，且一次只改一个参数组。
2. 运行任务，不要手动抢油门/姿态；必要时按 AG10 中止。
3. 执行 `python tools\analyze_telemetry.py`，保存摘要和对应 KSP.log 行。
4. AI 根据可观测症状提出一个小改动，例如晚点火只调 `BURN_ALTITUDE_MARGIN`，横向末端残差只调 `H_POS_KP_LOW`。
5. 先跑 `simulate_controller.py` 回归，再复制 config 到游戏并重飞同一 quicksave。
6. 连续通过至少 5 次带不同初始偏差的飞行后，才把船移远或增加上面级任务复杂度。

参数诊断规则：

| 症状 | 优先检查 | 首选动作 |
|---|---|---|
| 油门长时间 100%、仍高速下坠 | 落地质量、可用推力 | 减重/换发动机；不要先加大 PID |
| 点火明显过晚但 TWR 足够 | `BURN_ALTITUDE_MARGIN`、`STOP_DISTANCE_SAFETY` | 小幅提高前者 |
| 低空横向误差大、横速已经很小 | `H_POS_KP_LOW` | 每次提高约 10% |
| 接近网时左右穿越振荡 | `H_VEL_KP`、传感延迟 | 增加阻尼或降低位置增益 |
| 姿态始终顶住 12° | 早期弹道偏差 | 提前修正；不要先放宽末端倾角 |
| 网拒绝、速度正常但 tilt 异常 | 控制点/零件朝向 | 检查 probe core 控制方向和网 +Y |

AI 每轮应保留参数 diff、离线回归输出、飞行 telemetry 和 CAPTURE/REJECT 行。这样即使某次“看起来成功”，也能判断是控制器真正收敛还是碰巧撞进网窗。

0.4.0 的海上迭代正是这个流程的实例：首次通过虽满足 7.5 m/s 包线，却以 −7.19 m/s 捕获且耗尽燃料；提高燃料后暴露出近场 8 m/s 横移引发的追逐振荡；限速 3 m/s、降低近场位置增益并把未对中列为强制高度保持后，控制器稳定在网中心。最后通过软下降又发现挂点与甲板碰撞面不一致，于是把缆网平面抬到挂点先接触的位置，并在高度保持退出时复位垂直积分。最终实飞以 −0.55 m/s、1.46 m/s、1.8° 四点捕获且保留约 3.9 t 推进剂，说明成功来自闭环与几何一致性，而非碰撞或燃料耗尽。

0.5.0 把控制链路扩展到正常重力转弯、分离后上面级续飞、一级越过远地点再翻转、单次再入制动和低空受约束制导。实飞在距目标 128 m、高度 427 m 时继续平稳归中，进入塔架后缆索依次显示 `Open → Closing → Closed`，最终以 −0.62 m/s、0.02 m/s、0° 四点捕获；100 m 以下最大倾角 4.2°、油门饱和比例 0.0%。

0.6.0 把 10 km 以下的再规划改成“固定到达时间三次轨迹 → 500 m 近场 PID”两段式，并用船位、45 秒单向返航和 6 秒固定姿态转向把入口状态预先送入可达走廊。实飞入口误差约 347 m、横速 27.6 m/s；低空不再悬停平移，最终以 −0.63 m/s、0.09 m/s、0° 捕获。闭索控制同时从一次性居中改为连续跟踪挂点中心，捕获后实测柔索下挠 0.62–0.63 m。

当前开发轮把末段扩展到 30 km 固定轨迹、13.5 km 单向停车走廊和 2 km 强制门限，并把一级回收入口与 35 km 重力转向重新标定。2026-07-14 最终复验在 2 km 记录垂直 143.82 m/s、横向 15.48 m/s、误差 2.4 m，整个受约束高速段喷管/速度夹角峰值 13.16°；随后以垂直 −2.48 m/s、横向 0.54 m/s、倾角 0.2° 四点捕获。捕获器锁存首次获取的目标，解决横摆时 `Closing → Open`；验收器对捕获后角速度使用 1.5 秒低通，避免 Unity 关节求解器的单帧冲量清空连续稳定计时。
