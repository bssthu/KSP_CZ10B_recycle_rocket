# 2026-07-10 长征十号乙海上网系回收调研

## 已证实的方案

2026 年 7 月 10 日 12:15，长征十号乙从海南商业航天发射场起飞；约 6 分钟后一二级分离，一级垂直返回并被海上平台网系捕获。这是中国首次运载火箭一级可控回收，也是公开报道所称的全球首次运载火箭网系回收。火箭为 5 m 直径两级串联构型，首飞箭约 63 m，起飞重量约 760 t、推力约 890 t，回收状态近地轨道能力约 16 t。来源：[中国航天科技集团](https://www.spacechina.com/n25/n2014789/n2014804/c4646845/content.html)、[国家航天局](https://www.cnsa.gov.cn/n6758823/n6758838/c10761540/content.html)。

回收动作不是“整张网兜住箭底”，而是以下顺序：

1. 一级经历动力减速和气动减速，接近平台后再次点火。
2. 箭上相对导航持续测量网系位置；箭上控制器修正位置、速度和姿态。
3. 平台滑车同时主动移动四根“井”字形高强度绳索，形成箭—网协同接驳。
4. 箭上四个轻型挂索机构提前展开；挂钩与绳索接触后，网系吸收剩余动能。
5. 四周辅助绳先稳住箭体，底部自动锁紧平台再移动到箭下抱夹支撑。

动作描述来源：[中国新闻网的分阶段报道](https://www.chinanews.com/m/gn/2026/07-10/10656695.shtml)。四索、四钩和结构效率方面的公开说明见[每日经济新闻](https://www.nbd.com.cn/articles/2026-07-10/4466983.html)。

“领航者”平台长 144 m、宽 50 m、吃水 5.5 m、满载排水量 2.5 万 t，具备 DP2 动力定位能力；公开证据见[人民网海南](https://hi.people.com.cn/n2/2026/0624/c231190-41620075.html)及[中国船级社](https://www.ccs.org.cn/ccswz/articleDetail?id=202512040289644824)。这解释了方案的设计哲学：减轻箭上着陆腿与缓冲结构，把设备重量和捕获容差转移到可重复使用的海上基础设施。

公开资料没有给出索网尺寸、挂钩高度、允许入网速度/倾角、滑车行程和控制律。因此本项目中的 20 m × 20 m 网窗、7.5 m/s 法向速度、4 m/s 横向速度和 15° 倾角都是 KSP 验证参数，不应当被引用为真实火箭数据。

## KSP 可复现性结论

可以复现“可观察动作”和主要控制难点，但不能只靠原版碰撞体忠实复现柔索接触。KSP 1 的刚体、零件树和跨载具物理加载有三个限制：细绳碰撞在高速度下容易穿透；原生 strut 不是可动态捕获的绳；相距约数公里后另一载具会被 packed/on-rails，不能发生零件物理。

采用下列分工最稳妥：

| 真实系统 | KSP 实现 | 保真程度 |
|---|---|---|
| 箭上导航、发动机与姿态闭环 | kOS 级联反馈控制 | 高，受 KSP 气动/发动机模型限制 |
| 四个展开挂钩 | 四个 `CZ-10B Lightweight Catch Hook` | 中，首版不做展开动画 |
| 主动“井”字四索 | 四条三节点可视索；箭体进入塔架触发区后由外侧向内合拢 | 中，复现开网、合拢和等待闭合，不模拟真实滑车质量 |
| 索网缓冲吸能 | 四个弹簧—阻尼 `ConfigurableJoint`，捕获后索中点随箭体向下挠曲 | 中高，可测速度/行程/断裂并观察弹性下垂 |
| DP2 回收船 | 封闭船底、双浮筒和高塔架；自动任务先部署船再倒计时发射 | 中，KSP 原版无浪/风 |
| 辅助索和底部抱夹 | 捕获关节负责承载，一侧塔架展示静态收拢抱夹 | 低，公开资料没有足以复原真实夹具尺寸的细节，不宣称等比例 |

kOS 的官方文档说明脚本只在载具处于加载范围时完整工作，packed 载具的油门等功能受限，并警告不要盲目把物理范围扩大到数十/数百公里：[Vessel Load Distance](https://ksp-kos.github.io/KOS/structures/misc/loaddistance.html)。因此一级 probe core 必须是整箭 root，使分离后当前活动载具留在一级；上面级首轮仅做无控/简化飞行。

## AI 操作和自动拼装

kRPC 是成熟的“外部 AI 操作游戏”接口：可读取载具、轨道、部件和资源，发送油门/姿态/分级命令；官方 API 也能从 VAB/SPH 启动已有 craft（[LaunchVessel](https://krpc.github.io/krpc/csharp/api/space-center/space-center.html)）。但其标准 SpaceCenter API 只遍历和操作已经存在的部件树，并没有稳定的“在编辑器里拖一个零件并连接到节点”建造 API。

## G-FOLD 与当前终端制导取舍（2026-07-12）

NASA 的飞行机会计划资料把 G-FOLD 描述为实时计算燃料最优转移轨迹的算法，并记录了 Xombie 对横向转移轨迹的实飞验证（[NASA Flight Opportunities 2015 Annual Report](https://ntrs.nasa.gov/api/citations/20170000838/downloads/20170000838.pdf)）。这类方法的关键价值不是某一组固定增益，而是把终点位置/速度、推力上下限、倾角和可行时间同时放进约束优化。

公开的 [GFOLD_KSP](https://github.com/xdedss/GFOLD_KSP) 示例确实通过 kRPC 驱动 KSP，但仓库固定在 Python 3.6、`cvxpy==0.4.11`、SciPy 1.2.1 与旧版代码生成链。本机可用 Python 3.8、3.10 和 3.13，但当前均未预装 kRPC/CVXPY；直接照搬该环境会把演示可靠性绑定到已经过时的求解栈。

因此当前实现采用“G-FOLD 启发、非完整 G-FOLD”的分层方案：高空只安排清晰的滑行、远地点后返航点火和单次再入点火；6.5 km 以下每帧生成满足终点位置/速度的三次参考，并显式限制推力、横向加速度和倾角。150 m 以下未对中则悬停，12 m 以下等待索网闭合，最后 5 m 改用恒速穿网控制，避免固定最小剩余时间造成渐近悬停。离线点质量模型在 Python 3.10 与 3.13 上都执行同一套 250 组确定性扰动回归；kRPC 保留为以后接入现代 CVXPY 求解器和对比燃料消耗的可选实验接口，而不是当前观看演示的运行依赖。

所以自动拼装的现实选择按风险排序是：

1. 人工按清单拼一次，之后 VesselMover 反复生成预制 craft——本项目当前采用。
2. AI 修改一个已验证 `.craft` 模板中的少量参数/对称组；比从空文件生成安全得多。
3. 自写 kRPC Editor 服务或 KSP 编辑器插件，调用 `EditorLogic` 建造；可行但 API 非稳定、验证成本最高。

直接生成存档 `.sfs` 没有必要，也不应作为首选。craft 本身是 ConfigNode 文本，但连接节点、对称关系、persistent ID、root 与 staging 同时正确才算可用；由人完成首个黄金模板后再让程序变体生成，风险显著更低。
